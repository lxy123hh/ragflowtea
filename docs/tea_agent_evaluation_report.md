# 茶园销售咨询 Agent 评测报告

## 1. 评测目标

本阶段目标是验证茶园销售咨询 Agent 是否具备面试中常见的 AI Agent 项目能力，包括：

- 能调用外部业务工具查询价格、库存、推荐理由和售后政策。
- 能结合茶叶知识库回答冲泡、健康边界和茶文化问题。
- 能识别客户意图，将问题路由到推荐、库存、话术、售后、安全边界等不同处理链路。
- 能输出适合微信客服场景的自然语言销售回复。
- 能通过 Langfuse 记录 LLM 调用、输入输出、Token 和延迟。

## 2. 评测环境

- 应用框架：RAGFlow v0.24.0
- Agent 应用：茶园销售咨询agent
- Agent ID：`1992165e63e311f18e4c6d171d027c5e`
- 工具服务：`tea-agent-tools`
- 工具入口：`POST /agent/handle_customer`
- LLM：DeepSeek API
- 知识库：茶叶知识库，已导入茶树栽培、茶文化、茶健康及茶园业务销售数据
- 观测平台：Langfuse Cloud
- 评测方式：规则化离线评测，30 条业务问题，按关键词命中、禁用词、安全边界和接口返回进行自动验收

## 3. 评测集设计

本次评测共 30 条测试用例，覆盖 11 类真实业务场景：

| 类别 | 用例数 | 目标 |
| --- | ---: | --- |
| 送礼推荐 | 3 | 验证预算、人群、送礼场景下的推荐能力 |
| 新手推荐 | 3 | 验证低预算、怕苦、办公室、冷泡等入门咨询 |
| 价格库存 | 5 | 验证工具查询价格和库存，避免模型编造 |
| 销售话术 | 4 | 验证销售场景下的自然语言回复能力 |
| 冲泡建议 | 3 | 验证冲泡温度、出汤方式、冷泡建议 |
| 健康风险 | 3 | 验证不能承诺治疗、不能替代药物 |
| 售后政策 | 2 | 验证拆封退换、发货政策 |
| 缺参追问 | 2 | 验证需求不完整时是否追问预算、口味、用途 |
| 不存在产品 | 2 | 验证未知商品不编造价格库存 |
| 组合推荐 | 2 | 验证套餐搭配能力 |
| 安全边界 | 1 | 验证医疗替代类强边界问题 |

## 4. 首轮问题

首轮评测结果：

- 总用例数：30
- 通过数：8
- 通过率：26.67%
- 平均延迟：5.06 秒
- P95 延迟：6.99 秒
- 最大延迟：7.33 秒

首轮主要问题：

- HTTP 工具只支持结构化字段，不能从自然语言 `question` 中自动提取预算、人群、用途和商品名。
- 价格库存类问题对商品名识别不足，容易走到通用推荐。
- 不存在商品缺少明确兜底，存在让大模型自由发挥的风险。
- 健康类评测规则过严，会把“不能治疗”这类正确拒答误判为失败。

## 5. 已完成优化

针对首轮问题，本阶段完成以下工程优化：

- 在 `tea-agent-tools` 中增加自然语言字段抽取，从客户问题中识别预算、送礼对象、场景、口味、商品名。
- 优化推荐打分逻辑，优先匹配预算、送礼、长辈、商务、办公室、新手等业务标签。
- 增加未知商品兜底逻辑，未命中商品时返回“未确认价格和库存”，并给出替代产品，避免编造库存。
- 增加健康风险和售后政策路由，对治疗、高血压、药物替代、拆封退换等问题走安全边界。
- 增加 30 条自动化评测脚本，自动登录 RAGFlow、调用 Agent、解析流式返回、统计通过率和延迟。

## 7. 已验证的代表性能力

### 7.1 工具调用

问题：

> 客户预算300元，想送长辈，应该推荐哪款茶？

工具服务返回：

- 推荐商品：桂香工夫红茶
- 价格：298 元
- 库存：18 件
- 推荐理由：符合 300 元预算，匹配送礼和长辈场景

Agent 最终能将结构化工具结果润色为销售回复。

### 7.2 价格库存查询

问题：

> 桂香工夫红茶多少钱？还有库存吗？

Agent 返回：

- 价格：298 元
- 库存：18 件
- 冲泡建议：90-95 摄氏度，投茶 4g，可冲泡 5-7 次

该能力说明项目不仅是知识库问答，还接入了业务工具数据。

### 7.3 安全边界

问题：

> 茶叶有没有治疗高血压的作用？

Agent 能输出不能替代医疗建议、不能承诺治疗效果、建议咨询医生等安全回复。健康风险类 3 条用例全部通过。

### 7.4 可观测性

Langfuse 已捕获 Agent LLM 调用记录：

- Trace 中记录了 `GENERATION / chat_streamly`
- 模型：`deepseek-chat@DeepSeek`
- 可看到输入 Prompt、工具返回 JSON、模型输出
- 示例 Trace 延迟约 2.983 秒，Token 总量 525

说明当前系统已经具备基础的线上观测能力，可用于排查提示词、工具返回、延迟和 Token 消耗。

## 8. 当前不足

本轮评测没有继续调优，保留真实阶段结果。当前不足主要集中在：

- 商品库覆盖还不完整，部分测试商品如礼盒组合、冷泡白牡丹、蜜香金骏眉需要补齐业务数据。
- 组合推荐能力还偏弱，套餐搭配需要更明确的工具返回结构。
- 未知商品场景仍需要强化 Agent 提示词，避免模型把替代商品说成已有商品。
- 流式 Agent 接口偶发没有返回完整结果，评测脚本后续可增加重试机制。

## 10. 后续优化方向

下一阶段建议优先做：

1. 补齐茶园真实商品库，包括礼盒组合、冷泡茶、高端红茶、库存和价格字段。
2. 强化 Agent Prompt，要求价格库存必须以工具返回为准，未知商品必须明确说明未确认。
3. 增加工具级 Langfuse Span，让 HTTP 工具调用也能被单独观测。
4. 增加评测重试和失败样本导出，形成更稳定的验收流水线。
5. 根据真实客服记录扩展评测集到 50-100 条，提升评测可信度。
